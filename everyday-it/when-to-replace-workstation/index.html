Everyday IT · Workstations

Know when to stop repairing the symptom.

Cleanup and reinstallation can buy time, but repeated failures on an aging system can turn support into wasted effort.Temporary improvement is not the same thing as a healthy workstation.

Check the signalsBack to Troubleshooting

Signals that replacement belongs in the conversation

No single symptom proves a PC should be replaced. The pattern matters.

Performance

Basic clicks take seconds

If normal navigation, installs, reboots, and application launches are consistently painfully slow, the workstation itself becomes part of every ticket.

Resources

CPU or disk pressure never settles

Persistent 100% resource use after routine cleanup and reboot can indicate that more troubleshooting will deliver only temporary relief.

Repeat failures

The same software keeps breaking

If scanner software, browsers, Office, or other applications repeatedly fail to install or stay healthy, compare the cost of another repair cycle with replacement.

Hardware

Storage or another component is failing

Protect recoverable data first. Once hardware failure is established, repeated repair attempts can increase risk without restoring trust in the machine.

Temporary improvement can be misleading

A restart or cleanup may make an old system feel better for an hour or a day.

Short-term win

Document what improved

Temp cleanup, removing stale profiles, or a restart may restore usability. That is useful evidence, but it does not erase persistent resource pressure or recurring failures.

Business impact

Count technician time and user downtime

When every peripheral or application issue becomes a long session because the PC itself is slow, replacement can be the lower-risk operational choice.

Escalate

Move from repair to recommendation

Document age, performance symptoms, failed repairs, hardware concerns, and the user's dependency on the system so the replacement decision is based on evidence.

Do not confuse “working again” with “worth continuing to repair.”

Support should restore service, but it should also recognize when the platform is becoming the recurring root cause.
