Shared Mailbox Not Showing in Outlook

A practical troubleshooting guide for when a shared mailbox has been assigned correctly but never appears in Outlook. Real-world troubleshooting. Not guesswork.

Written by Michael Miller · Published August 9, 2026 · Last reviewed August 16, 2026

Estimated Time

10–15 Minutes

Difficulty

Intermediate

Technologies

Microsoft 365 / Outlook / Exchange Online

KT Reference

KT-000001

The Problem

The shared mailbox was assigned, but Outlook never showed it.

A user had been granted access to a Microsoft 365 shared mailbox, but the mailbox did not automatically appear in Outlook as expected.

This can be confusing because the Microsoft 365 permissions may look completely correct in the admin portal while the Outlook client still shows no sign of the mailbox.

Before rebuilding profiles or making unnecessary changes, the first job is to determine whether the problem is permissions, Exchange propagation, automapping, or Outlook itself.

Environment

Applies To

This troubleshooting flow is intended for Microsoft 365 environments using Exchange Online with new or classic Outlook for Windows. The mailbox-add and synchronization behavior differs between those clients.

Platform

Microsoft 365

Mail

Exchange Online

Client

Microsoft Outlook

Feature

Shared Mailboxes

Before You Start

Verify the basics before changing anything.

Confirm that the user has actually been granted the correct shared mailbox permissions in Exchange Online or the Microsoft 365 admin tools.

Also confirm that enough time has passed for Microsoft 365 changes to propagate. Permission changes are not always immediate.

If the mailbox is business-critical, avoid rebuilding Outlook profiles or making broad client-side changes until you know the issue is not simply permission propagation or automapping behavior.

Resolution

How We Solved It

Start with the server-side configuration before changing Outlook. Confirm the mailbox and permissions are correct, then work outward toward automapping and the Outlook client.

Step 1

Confirm mailbox permissions

In Microsoft 365 or the Exchange admin tools, open the shared mailbox and confirm the affected user has the required mailbox permissions.

Verify Full Access is assigned. Remember that Send As and Send on Behalf are separate permissions and do not control whether the mailbox appears automatically.

Step 2

Allow time for Exchange Online propagation

Newly assigned permissions are not always immediate. Give Microsoft 365 time to process the change before troubleshooting Outlook.

Tip

If permissions were only added a few minutes ago, don't change five other things while waiting. Let Exchange catch up first.

Step 3

Restart Outlook

Close Outlook completely and reopen it. If automapping is functioning correctly, the mailbox may appear automatically.

Step 4

Add the mailbox manually if necessary

If permissions are confirmed but the mailbox still does not appear, add it manually before rebuilding the Outlook profile.

In new Outlook, right-click the account in the Folder pane and select Add shared folder or mailbox. In classic Outlook, use File > Account Settings > Account Settings, select the account, and add the mailbox under More Settings > Advanced.

See Microsoft's current shared mailbox instructions for Outlook when the client interface differs from these steps.

Warning

Do not rebuild an Outlook profile until permissions, propagation time, and automapping have been verified. A profile rebuild often creates extra work without solving the real issue.

Verification

Confirm the shared mailbox now appears in Outlook.

Verify folders open successfully and no permission errors are displayed.

If Send As or Send on Behalf permissions were configured, send a test email to verify functionality.

Restart Outlook one final time to confirm the mailbox remains available.

Real-World Notes

The most common mistake is assuming Outlook is broken.

In production, Exchange Online propagation delays account for many "missing mailbox" tickets.

Automapping is convenient, but it should never be treated as proof that permissions are correct.

Verify Exchange first. Troubleshoot Outlook second.

Verify the service before rebuilding the client.

Start with Exchange permissions and propagation before making client-side changes. Most shared mailbox problems are resolved without rebuilding Outlook once the server configuration has been verified.
