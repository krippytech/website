Shared Mailbox Not Showing in Outlook

A practical troubleshooting guide for when a shared mailbox has been assigned correctly but never appears in Outlook. Real-world troubleshooting. Not guesswork.

Estimated Time

10–15 Minutes

Difficulty

Intermediate

Technologies

Microsoft 365 / Outlook / Exchange Online

KT Reference

KT-0000XX

The Problem

The shared mailbox was assigned, but Outlook never showed it.

A user had been granted access to a Microsoft 365 shared mailbox, but the mailbox did not automatically appear in Outlook as expected.

This can be confusing because the Microsoft 365 permissions may look completely correct in the admin portal while the Outlook client still shows no sign of the mailbox.

Before rebuilding profiles or making unnecessary changes, the first job is to determine whether the problem is permissions, Exchange propagation, automapping, or Outlook itself.

Environment

Applies To

This troubleshooting flow is intended for Microsoft 365 environments using Exchange Online and desktop Outlook with shared mailbox access.

Platform

Microsoft 365

Mail

Exchange Online

Client

Microsoft Outlook

Feature

Shared Mailboxes

Before You Start

Verify the basics before changing anything.

Confirm that the user has actually been granted the correct shared mailbox permissions in Exchange Online or the Microsoft 365 admin tools.

Also confirm that enough time has passed for Microsoft 365 changes to propagate. Permission changes are not always immediate.

If the mailbox is business-critical, avoid rebuilding Outlook profiles or making broad client-side changes until you know the issue is not simply permission propagation or automapping behavior.

Resolution

How We Solved It

Start with the server-side configuration before making changes to Outlook. The goal is to confirm that the mailbox and permissions are correct, then determine whether Outlook is simply waiting on automapping or needs the mailbox added manually.

Step 1 — Confirm mailbox permissions

In the Microsoft 365 or Exchange admin tools, open the shared mailbox and confirm the affected user has the required mailbox permissions.

For normal shared mailbox access, verify Full Access is assigned. Send As or Send on Behalf permissions are separate and do not by themselves cause the mailbox to appear in Outlook.

Step 2 — Allow time for the change to propagate

Newly assigned Exchange Online permissions may not appear immediately. If the permissions were just added, allow time for Microsoft 365 to process the change before troubleshooting the Outlook profile.

Step 3 — Restart Outlook

Close Outlook completely and reopen it. If automapping is working, the shared mailbox may appear automatically after the permission change has propagated.

Step 4 — Add the mailbox manually if needed

If the mailbox still does not appear but the permissions are confirmed, add the shared mailbox manually in Outlook rather than immediately rebuilding the user's entire Outlook profile.

Verification

Confirm the mailbox is actually usable.

Verify that the shared mailbox now appears in Outlook and that the user can open the mailbox folders without permission errors.

Send a test message from the shared mailbox if Send As or Send on Behalf permissions are part of the configuration.

If the mailbox was added manually, close and reopen Outlook one more time to confirm the configuration persists.

Real-World Notes

What usually causes wasted time here.

The biggest mistake is assuming Outlook is broken simply because the mailbox does not appear immediately.

Exchange Online permission changes can take time to propagate, and automapping behavior can make a perfectly valid permission assignment look like it failed.

Rebuilding an Outlook profile too early can create additional work without addressing the actual cause.

Lessons Learned

Verify the service before rebuilding the client.

Start with Exchange permissions and propagation before making client-side changes.

Treat automapping as a convenience, not proof that mailbox permissions are correct or incorrect.

If permissions are valid and the mailbox is still missing, adding it manually is usually a better next step than immediately rebuilding the entire Outlook profile.
